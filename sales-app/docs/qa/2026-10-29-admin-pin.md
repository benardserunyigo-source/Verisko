# Admin-created PIN-only sign-in

Main sign-in asks for one 8-digit PIN. Admin opens Office tools & help → Team & settings and creates a separate PIN for an existing team member (or uses Create my sign-in PIN). PINs are generated randomly, shown once, and not saved as plain text. Admin can replace or turn off a PIN. Replacing or disabling revokes that PIN's sessions. No phone, email or name is needed when signing in with the new PIN.

Existing phone/4-digit PIN and email sign-in remain under Other sign-in options so existing staff are not locked out. New staff still complete the existing invite and identity steps before Admin creates their PIN. This change does not bypass an overdue ID check, add accounts, change roles, alter customer records or send PINs to people.

Server boundary: Admin only creates/revokes; protected owner restrictions retained. A secret-keyed lookup finds the account without scanning passwords, and a separate salted PBKDF2 hash verifies the PIN. Signed session tokens select the separate private record; ordinary workspace data carries no PIN, lookup or hash. Every attempt consumes a compare-and-set protected limit of 20 attempts per platform connection IP per 15 minutes, including unknown/malformed PINs. Missing IP fails into one shared limit. Concurrent conflicts fail closed. PIN records use compare-and-set version updates; removed users and unsupported roles cannot sign in. Existing resource handlers continue enforcing their current roles.
